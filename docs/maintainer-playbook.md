# Maintainer Playbook

This project should build public trust through visible, routine maintenance.

## Weekly

- Triage new issues.
- Reproduce bug reports.
- Label issues as `bug`, `enhancement`, `question`, `documentation`, or `good first issue`.
- Convert vague requests into small actionable issues.

## Before Each Release

- Run tests.
- Run example commands.
- Check that output remains plain-language and non-alarmist.
- Review `PRIVACY.md` and `SECURITY.md` if data handling changed.
- Update `CHANGELOG.md`.

## Codex/API Credit Use

Good uses:

- Draft reproduction steps from messy bug reports.
- Suggest test cases for edge cases.
- Review PRs for hidden assumptions or unclear output text.
- Draft release notes from merged commits.
- Summarize issue themes into roadmap items.

Avoid:

- Auto-merging unreviewed changes.
- Generating claims about public-health meaning without human review.
- Adding analytics or network services without privacy review.
